> Status: shipped and independently verified
> Date: 2026-08-30
> Spec: `docs/specs/v0.1.0-stable-release.md`
> Plan: `docs/plans/v0.1.0-stable-release.md`

## Shipped behavior

Side Glance v0.1 promotes the verified beta lifecycle implementation to the
stable npm `latest` channel and GitHub Latest Release. Homebrew remains the
recommended durable installation, with `side-glance@latest` as the explicit npm
and npx path. Claude Code and Codex remain locally contract-audited; Gemini,
OpenCode v1, Aider, and Intel macOS retain their experimental labels.

The release does not change runtime behavior. It synchronizes version metadata,
the public installation journey, changelog, structured data, and stable channel
validation around the immutable build produced from `v0.1.0`.

## Release sequence

1. Merge the reviewed release-preparation branch into protected `staging` after
   every local, CI, Vercel, distribution, and browser gate passes.
2. Promote literal `staging` to protected `main` with a merge commit and verify
   the exact main SHA in CI and Vercel production.
3. Create one protected annotated `v0.1.0` tag at that exact main commit.
4. Let `release.yml` assemble, test, checksum, attest, and stage the native and
   npm artifacts; publish npm through trusted OIDC to `latest`; then finalize a
   non-prerelease immutable GitHub Latest Release.
5. Independently verify public npm metadata/integrity/provenance, GitHub assets,
   `SHA256SUMS`, attestations, the Linux x64 binary, and fresh npm/npx paths.
6. Open the generated formula as a separate protected Homebrew tap PR; merge it
   only after every tap CI platform passes, then run a public brew smoke.

## Stop conditions

- The package version, lockfile, tag, changelog, and release manifest differ.
- The tag is not protected, annotated, or reachable from the verified main SHA.
- Any required local/remote gate or production deployment is not green.
- npm or GitHub already contains `0.1.0` with different bytes.
- A stable wording change removes an experimental provider/platform qualifier.
- An environment requests approval from a release operator who has not reviewed
  the exact candidate.

## Rollback

Before tagging, repair or revert only through protected pull requests. After the
tag or npm publication, do not move the tag or replace release bytes. Preserve
`0.1.0` as the audit record, deprecate the npm version if warranted, and fix
forward with `0.1.1`. Retry the release workflow only when it will reuse the
same tagged workflow and byte-identical bundle. Repair a Homebrew-only failure
inside the tap without mutating the immutable release.
