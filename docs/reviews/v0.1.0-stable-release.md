# Review: Side Glance v0.1.0 stable release

> Spec: `docs/specs/v0.1.0-stable-release.md`
> Plan: `docs/plans/v0.1.0-stable-release.md`
> Status: shipped and independently verified
> Reviewed: 2026-08-30

## Outcome

The release promotes the verified beta lifecycle implementation to `0.1.0`
without changing runtime behavior. Package metadata, CLI bootstrap guidance,
current READMEs and website copy, structured data, changelog, launch records,
and release-channel validation now agree on the stable npm `latest` channel.
The existing `beta` channel and every provider or platform maturity qualifier
remain intact.

The Ultracite comparison supported one process change: make the stable version
change an explicit reviewable release-preparation pull request. Side Glance
retains its own tag-driven workflow because it additionally produces native
archives, checksums, attestations, a release manifest, and a Homebrew formula.

## Five-axis review

### Correctness

- `package.json`, `package-lock.json`, changelog, release validator, CLI output,
  structured data, and current-version tests agree on `0.1.0`.
- Stable install paths use `side-glance@latest`; prerelease validation still
  proves that `0.1.0-beta.12` belongs on `beta`.
- Current public copy calls the package stable while retaining the experimental
  Gemini, OpenCode v1, Aider, and Intel macOS qualifiers.
- The stable contract first failed against the beta.12 tree for the expected
  metadata and documentation mismatches, then passed after the promotion.

### Simplicity

- No release dependency, parallel publishing path, or runtime branch was added.
- The existing manifest validator remains the release-channel source of truth.
- The release is a metadata and public-journey promotion of already verified
  behavior, keeping the candidate small and auditable.

### Architecture

- Protected `staging` and `main` remain the only promotion path.
- One annotated protected tag at the verified main commit remains the sole
  immutable input to npm, GitHub, native, checksum, attestation, and formula
  assembly.
- npm is published through trusted OIDC and GitHub is finalized only after the
  staged artifacts and public package checks agree.

### Security and privacy

- The release path introduces no long-lived npm token and does not alter runtime
  data access, provider hooks, filesystem targets, or network behavior.
- Apache-2.0 is consistent across repository license text, npm metadata, and the
  corrected dynamic license badge target.
- Protected tags, provenance, attestations, checksums, immutable releases, and
  fix-forward recovery remain mandatory.
- `npm-release` has no required environment reviewer while only one qualified
  release operator exists. The maintainer verified the exact protected main SHA
  and annotated tag; a self-review placeholder would not be an independent gate.
  Add a required reviewer when a second qualified operator is available.

### Performance and distribution

- Runtime code and dependency count are unchanged, so the candidate adds no
  bundle, startup, memory, or network cost.
- Packed npm, standalone native, release-channel, website, and rendered-output
  paths all pass the repository gates.
- The release workflow retains native archives for four targets, the npm
  tarball, manifest, formula, checksum file, and attestations.

## Browser evidence

- Desktop: at 1280×720, the stable install action and terminal were in bounds,
  document width equaled viewport width, the page completed its loader, and all
  images loaded.
- Mobile: at 390×844, document width remained 390px, the terminal and install
  action stayed in bounds, and the input retained a 16px font size.
- Interaction: pointer activation copied the stable guided-setup commands and
  changed the accessible label to confirm the copy.
- Console/assets: no warning or error was logged and no image failed.
- Failure recovery: a missing route showed `Page not found`, recovery guidance,
  and discoverable sitemap/`llms.txt` links without a console error.
- Reduced motion: the browser reported the normal OS preference and the selected
  browser exposes no preference override. The reduced path remains enforced by
  source, media-query, hydration, and rendered-output contracts.
- Keyboard evidence limitation: the selected browser's documented key injector
  did not dispatch Tab or Enter to this page in background or foreground mode.
  Controls remain native buttons, pointer behavior passed, and the existing
  keyboard semantics and focus-visible source contracts are green; this review
  does not misstate the injector limitation as a manual keyboard pass.

## Required findings resolved

1. Replace the stale beta.12 package and lockfile version with `0.1.0`.
2. Move durable npm and npx guidance from `@beta` to `@latest`.
3. Replace current beta public copy and structured metadata with stable v0.1
   language while retaining evidence qualifiers.
4. Add a dated stable changelog entry and correct compare links.
5. Replace the static MIT badge path with npm's published license metadata and
   stop the version/release badges from selecting prereleases.
6. Update the release guide and launch record for stable/latest publication and
   immutable fix-forward recovery.
7. Add a focused stable contract that guards metadata, public copy, structured
   data, channel policy, and the preserved beta channel.
8. Distinguish supported Apple Silicon macOS from experimental Intel macOS in
   the package README's opening support statement.
9. Remove the stale `beta artifact` phrase from future stable formula generation
   and add a regression assertion; the public tap corrected the cosmetic comment
   without changing the immutable v0.1.0 URLs or checksums.

No required code, release, browser, registry, provenance, or Homebrew finding
remains. The delayed optional review's `@latest` timing findings became obsolete
when npm publication completed; the release guide now explicitly prohibits using
`@latest` for unpublished-candidate verification and defers channel-changing copy
to the protected post-publication path.

## Release stop conditions

- Do not tag unless the exact protected main SHA is green in CI and Vercel.
- Stop if npm or GitHub already contains `0.1.0` with different bytes.
- Stop if the tag is not annotated, protected, or reachable from verified main.
- Never move the tag or replace public bytes; deprecate and fix forward with
  `0.1.1` if post-publication repair is required.
